## 引言
- 目标：为设备生产企业与招标单位提供在线发布招标、投标、查询筛选与流程管理能力。
- 范围：前端 Web（Vue2 + ElementUI）、后端（Node.js + Express）、关系型数据库（MySQL）。
- 角色：管理员、招标单位（tender）、制造商（manufacturer）、游客。
- 约束：课程设计取舍，功能以核心流程为主，留出扩展点。

## 总体设计
- 架构：前后端分离，REST API；前端 SPA 通过 `axios` 调用后端；JWT 会话；MySQL 持久化。
- 技术栈：
  - 前端：`Vue 2.x`、`Vue Router`、`Vuex`、`Element UI`。
  - 后端：`Node.js 18+`、`Express`、`mysql2`、`dotenv`、`bcrypt`、`jsonwebtoken`。
  - 开发工具：`eslint`、`babel`、`npm`、`Trae IDE`。
- 部署形态：开发使用 `npm run serve`（8081），后端 `node server/app.js`（3000）。
- 核心流程：
  1) 招标单位发布招标；
  2) 制造商浏览、筛选、查看详情；
  3) 制造商提交投标；
  4) 管理员/招标单位审核/定标（可选）；
  5) 留言板沟通（可选）。

## 模块设计
### A. 身份与授权模块（Auth）
- 职责：注册、登录、角色分配、会话维护、路由守卫。
- 前端：
  - `store/auth`：`state: { token, user, role }`；`getters.isAuthenticated`；`actions.login/logout/register`。
  - 路由守卫：基于 `isAuthenticated` 与 `role` 控制访问。
- 后端：
  - `/api/auth/register`、`/login`、`/profile`；密码哈希；JWT 颁发与校验中间件。
- 交互：登录成功后写入 `token` 与 `role`，前端显示不同导航按钮。

### B. 招标管理模块（Tender Management）
- 职责：发布、列表、详情、筛选、分页。
- 前端：
  - 视图：`Home.vue`（列表、筛选、分页）、详情对话框。
  - 服务：`services/api.tenderApi`：`list(params)`、`create(payload)`、`get(id)`。
- 后端：
  - `GET /api/tenders` 支持 `keyword/status/page/pageSize`；统一响应 `{ data, total }`。
  - `POST /api/tenders` 角色 `tender`；字段校验与默认值。
- 关键点：统一前端解析 `normalizeListResponse`，防止数组/对象差异导致渲染异常。

### C. 投标管理模块（Bid Management）
- 职责：制造商对招标项目提交投标数据；后台存储与校验。
- 前端：
  - 对话框：`bidDialogVisible`；表单 `bidForm`（总金额、生产日期、质保期、保证金缴纳日期、文档链接）。
  - 校验：金额必填且大于 0；登录角色为 `manufacturer`。
  - 服务：`services/api.bidApi.createBid(payload)`。
- 后端：
  - `POST /api/bids` 校验制造商身份；关联 `tender_project_id`；状态默认 `submitted`。

### D. 留言板模块（Message Board）
- 职责：简单的项目沟通与公告评论。
- 前端：
  - 视图：`views/messages/MessageBoard.vue`（列表 + 发送）。
  - 数据：`messageList`、`newMessage`；分页与时间戳显示。
- 后端：
  - `GET /api/messages`、`POST /api/messages`；可按项目过滤 `tender_id`。

### E. 管理控制台模块（Admin Dashboard）
- 职责：用户与项目管理；导入导出（课程设计可选）。
- 后端：
  - `GET /api/admin/users`、`GET /api/admin/tenders`；权限中间件 `role=admin`。

### F. 公共模块（Common）
- 通用组件与工具：分页组件、统一错误提示、axios 实例、日期格式化。

## 用户界面设计
### 导航与页面结构
- 顶部导航：Logo、根据角色显示的操作按钮（进入系统、发布招标、留言板、登录/注册/退出）。
- 首页（`Home.vue`）：
  - 欢迎区：系统简介文案。
  - 招标筛选条：关键字 + 状态 + 搜索/重置；回车触发搜索。
  - 招标表格：项目编号、设备名称、型号、数量、截止日期、操作（查看详情、立即投标）。
  - 分页：`prev, pager, next, sizes, total`；页码与页尺寸联动。
  - 右侧用户指南：四项简明指引（注册、发布、投标、常见问题）。
- 详情对话框：`el-descriptions` 两列；底部操作（关闭、登录参与投标/立即投标）。
- 投标对话框：`el-form` 字段齐全，主按钮禁用态随 `submittingBid`。
- 留言板：消息列表、输入框与发送按钮；支持按项目筛选（可选）。

### 组件与样式
- 基于 `Element UI`：`el-form`、`el-input`、`el-select`、`el-table`、`el-pagination`、`el-dialog`、`el-descriptions`。
- 自定义样式：卡片间距、表格宽度、分页布局；移动端最小适配（课程设计可选）。

### 交互流程（示例：投标提交流程）
1. 用户在首页点击某项目“立即投标”。
2. 若未登录，提示并跳转登录；若角色非制造商，提示“只有厂商角色可以参与投标”。
3. 表单校验金额 > 0；提交后主按钮进入 `loading`。
4. 成功：提示“投标提交成功”，关闭对话框并重置表单；失败：显示后端错误消息。

## 数据库设计
### ER 概述
- 实体：`users`、`tenders`、`bids`、`messages`、（可选：`attachments`、`roles`）。
- 关系：
  - `users (1) —— (n) tenders`（发布者）。
  - `users (1) —— (n) bids`（投标者）。
  - `tenders (1) —— (n) bids`（项目-投标）。
  - `tenders (1) —— (n) messages`（项目-留言，可选全局）。

### 表结构设计（DDL 摘要）
```sql
-- 用户
CREATE TABLE users (
  id INT AUTO_INCREMENT PRIMARY KEY,
  username VARCHAR(64) NOT NULL UNIQUE,
  email VARCHAR(128) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  role ENUM('admin','tender','manufacturer') NOT NULL DEFAULT 'manufacturer',
  is_active TINYINT(1) NOT NULL DEFAULT 1,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 招标项目
CREATE TABLE tenders (
  id INT AUTO_INCREMENT PRIMARY KEY,
  project_number VARCHAR(64) NOT NULL UNIQUE,
  equipment_name VARCHAR(255) NOT NULL,
  model VARCHAR(128),
  quantity INT NOT NULL,
  deadline DATE NOT NULL,
  deposit DECIMAL(12,2) DEFAULT 0,
  packaging_requirements TEXT,
  description TEXT,
  status ENUM('open','closed') NOT NULL DEFAULT 'open',
  publisher_id INT NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (publisher_id) REFERENCES users(id)
);

-- 投标
CREATE TABLE bids (
  id INT AUTO_INCREMENT PRIMARY KEY,
  tender_project_id INT NOT NULL,
  bidder_id INT NOT NULL,
  total_amount DECIMAL(14,2) NOT NULL,
  production_date DATE,
  warranty_period VARCHAR(64),
  deposit_payment_date DATE,
  bid_document VARCHAR(512),
  status ENUM('submitted','reviewed','awarded','rejected') DEFAULT 'submitted',
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (tender_project_id) REFERENCES tenders(id),
  FOREIGN KEY (bidder_id) REFERENCES users(id)
);

-- 留言
CREATE TABLE messages (
  id INT AUTO_INCREMENT PRIMARY KEY,
  tender_id INT,
  author_id INT NOT NULL,
  content TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (tender_id) REFERENCES tenders(id),
  FOREIGN KEY (author_id) REFERENCES users(id)
);
```

### 索引与约束
- `tenders.project_number` 唯一索引；`tenders.status` 普通索引；`bids.tender_project_id` 复合索引建议（`tender_project_id, status`）。
- 外键约束保证关联完整性；必要时在课程设计中可弱化为应用层校验。

### 数据字典（摘录）
- `users.role`：用户角色枚举。
- `tenders.status`：`open`/`closed`；状态随 `deadline` 或发布方操作改变。
- `bids.status`：提交流程状态枚举。

## 接口设计
### 认证
- `POST /api/auth/register`：注册；
- `POST /api/auth/login`：登录，返回 `token`、`role`、`user`；
- `GET /api/auth/profile`：获取当前用户信息；

### 招标
- `GET /api/tenders`：查询；`params: keyword, status, page, pageSize`；返回 `{ data, total }`。
- `GET /api/tenders/:id`：详情；
- `POST /api/tenders`：发布（角色：tender）。

### 投标
- `POST /api/bids`：提交投标（角色：manufacturer），请求体见“投标表结构”。
- `GET /api/bids?tenderId=...`：按项目查询投标列表（管理员/招标单位）。

### 留言
- `GET /api/messages?tenderId=...`：查询留言；
- `POST /api/messages`：发表留言（登录）；

## 安全设计
- 身份认证：JWT；后端中间件校验并在 `req.user` 注入用户信息。
- 授权：按 `role` 控制 API；路由守卫控制前端页面入口。
- 输入校验：服务端校验金额、日期与字符串长度；防止 XSS/SQL 注入。
- 密码：`bcrypt` 哈希；禁止明文存储。

## 性能与容量规划
- 列表：分页 + 可选关键词索引；表格使用 `:page-size` 控制每页数据量。
- 并发：课程设计场景下单机足够；可水平扩展后端服务与数据库读写分离。
- 资源：静态资源走浏览器缓存；接口超时与重试策略按需设置。

## 错误处理与日志
- 前端：统一 `this.$message.error(...)` 展示；重试与兜底提示。
- 后端：按层记录：访问日志、应用日志、异常日志；返回统一错误结构 `{ message, code }`。

## 部署与运维
- 开发：`npm run serve`（前端），`node server/app.js`（后端）。
- 配置：`.env` 管理数据库连接、JWT 密钥、管理员默认密码等。
- 监控：基础健康检查接口（可选 `/api/health`）。

## 测试计划
- 单元测试：服务层与工具函数（可选）。
- 集成测试：接口端到端（登录、发布、查询、投标）。
- UI 冒烟：关键页面加载与交互流程。

- 数据为演示，不用于真实业务；
- 可能存在浏览器编码与本地化差异，需保持 UTF-8。
