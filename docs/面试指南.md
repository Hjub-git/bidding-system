# 面试指南 —— 机电设备在线招投标系统

> 这份文档不是"项目说明"，而是帮你**在面试里把这个项目讲出技术深度**的底稿。
> 你的情况：Java 只做过算法题，Spring / Vue 之前都不会。下面每一节都按"面试官会怎么问 → 你怎么答"来组织，照着理解，别背原话。

## 0. 一句话开口（30 秒自我介绍里带一句）

> "我把一个原本用 Node.js + Express 写的招投标系统，用 **Spring Boot 3 + MyBatis-Plus + Spring Security + JWT** 重写了后端，重新设计了数据库，并且把原来几个明显的安全和工程问题都修掉了。项目里三种角色（厂家 / 招标单位 / 管理员），覆盖了登录鉴权、分页查询、事务、逻辑删除、越权防护这些点。"

关键词命中：**分层架构、统一返回、全局异常、JWT 鉴权、事务、数据库设计、逻辑删除、防重复投标、越权防护**——每个都是面试高频点。

## 1. 技术栈与整体分层

| 层 | 技术 | 你负责的部分 |
|---|---|---|
| 后端 | Spring Boot 3.2.5 + Java 17 | 全部重写 |
| 持久层 | MyBatis-Plus 3.5.7（`mybatis-plus-spring-boot3-starter`）| BaseMapper / 分页 / 逻辑删除 / 自动填充 |
| 安全 | Spring Security + JWT（jjwt 0.12.5）| 无状态鉴权 |
| 数据库 | MySQL 8 | 重设计 schema + seed |
| 前端 | Vue 2.6 + Vuex + Element UI + axios | 保留，仅做了最小对接改动 |
| 构建 | Maven 3.9.9 | 阿里云镜像 |

**分层结构（这是"工程化"最直接的体现，画出来）：**

```
Controller（接收请求、参数校验、调 Service）
   ↓  只传 DTO（入参对象）
Service（业务逻辑、事务、越权校验）  ← 核心，所有"规则"都在这层
   ↓
Mapper（MyBatis-Plus，复杂联表用自定义 SQL）
   ↓
Entity（对应数据库表）
```

出参用 **VO**（view object），入参用 **DTO**（data transfer object），实体用 **Entity**——三层对象分离，不把数据库表直接暴露给前端。

## 2. 统一返回 + 全局异常（高频：怎么写一个"规范"的后端）

**统一返回体 `Result<T>`：**
```java
{ "code": 200, "message": "ok", "data": {...} }
```
- `code` 与 HTTP 状态码对齐（200 成功 / 400 参数错 / 401 未登录 / 403 无权限 / 404 不存在 / 500 服务器错）。
- 分页统一用 `PageResult<T> = { items, total }`。
- 好处：前端只需要解包 `data`，错误统一提示 `message`。

**全局异常 `@RestControllerAdvice + @ExceptionHandler`：**
- 业务异常 `BusinessException`（带 code + message）直接抛，由处理器转成统一响应。
- 参数校验失败（`@Valid` + `@NotBlank/@NotNull/@Min`）取第一条错误提示。
- 兜底 `Exception` 记日志，对外只给"服务器内部错误"，**不暴露内部细节**（防信息泄露）。

**面试答法：** "不用每个方法 try/catch，我自定义一个 `BusinessException`，Service 层遇到业务不满足就抛，交给 `@RestControllerAdvice` 统一处理，返回统一格式。这样 Controller 很干净，错误处理也一致。"

## 3. 安全：Spring Security + JWT（必问，重点准备）

**为什么用 JWT 而不是 Session：**
- JWT **无状态**：服务端不存会话，只靠签名验真伪，方便分布式横向扩展。
- 登录成功签发 token，前端放 `localStorage`，之后每次请求带 `Authorization: Bearer <token>`。

**流程（能讲清楚这条链路就赢一半）：**
1. 登录 → `BCryptPasswordEncoder.matches()` 校验密码 → `JwtUtil.generateToken()` 签发 token。
2. 每个请求 → `JwtAuthenticationFilter`（继承 `OncePerRequestFilter`）解析 token → 把用户塞进 `SecurityContext`。
3. 接口授权用 `@PreAuthorize("hasRole('ADMIN')")` 这类**方法级**注解（`@EnableMethodSecurity` 开启）。
4. 未登录/无权限 → `AuthenticationEntryPoint` / `AccessDeniedHandler` 统一返回 401 / 403 的 JSON。

**关键点逐个说：**
- 密码**绝不存明文**，用 `BCryptPasswordEncoder`（加盐哈希，同密码每次哈希结果都不同）。
- 登录失败统一提示"用户名或密码错误"，**不暴露**到底是哪个错（防用户名枚举）。
- `LoginUser` 实现 `UserDetails`，把角色映射成 `ROLE_TENDER` 这种 authority，`hasRole` 才能生效。

## 4. 数据库设计（面试官爱问"你的表怎么设计的"）

**三张"人"表拆开，用外键关联（第三范式）：**
- `users`：所有账号，用 `role` 字段区分 manufacturer / tender / admin。
- `manufacturers`（厂家档案）、`tender_units`（招标单位档案）：各自 `user_id` 关联 `users`，**一对一**（`UNIQUE(user_id)`）。

**四个值得主动讲的点：**

1. **逻辑删除**：`tender_projects / bids / messages / replies` 都有 `deleted` 字段（0/1）。删除 = `UPDATE deleted=1`，不物理删。
   - 好处：数据可追溯、误删可恢复；MyBatis-Plus 用 `@TableLogic` 自动在增删改查里带上 `deleted=0`。
2. **唯一约束兜底**：`bids` 表 `UNIQUE(manufacturer_id, tender_project_id)`——**一个厂家对一个项目只能投一次**，由数据库层保证，防止并发下重复投标（应用层先查、数据库层兜底，双重保险）。
3. **金额用 `DECIMAL(15,2)`，日期用 `DATE/DATETIME`**，绝不用 `double`（精度丢失）或 `varchar`（不能比较/计算）。
4. **索引**：`status`、`deadline`、`manufacturer_id` 等常查询列建索引；外键保证引用完整性。

## 5. 事务（高频："@Transactional 怎么用、什么时候失效"）

注册接口是**两步**：插入 `users` + 插入厂家/招标单位档案。用 `@Transactional(rollbackFor = Exception.class)` 保证**原子性**——两步要么都成功要么都回滚。

**面试可能追问（提前想好）：**
- `rollbackFor = Exception.class` 为什么显式写？——因为默认只对 `RuntimeException` 回滚，`Exception` 不回滚。
- 什么时候会失效？——同类内部方法自调用、方法非 public、异常被 catch 掉、数据库引擎不是 InnoDB。能说出前两个就是加分项。

## 6. 我"修掉的硬伤"（这是体现"优化/工程能力"的部分，一定主动讲）

原项目是 Node.js 写的，有几个明显问题，我重写时全修了：

| 原问题 | 现在怎么修 |
|---|---|
| **越权漏洞**：接受/拒绝投标不校验是不是自己的项目 | `decideBid` 里先查项目归属，招标单位只能处理**本单位**项目的投标，否则 403 |
| **管理员密码每次启动被重置** | 密码只在 seed 时初始化一次，bcrypt 存库 |
| **`.env` 里明文数据库密码提交** | 配置改读环境变量 `${DB_PASSWORD}`，本地才给默认值 |
| **`/api/tenders/mine` 永远 500**（代码里引用未定义变量） | 重写为干净的 `/api/my-tenders`，已实测通过 |
| **可重复投标** | 应用层查重 + 数据库唯一约束双层兜底 |
| **无分层、无异常处理、无统一返回** | 全部分层 + `@RestControllerAdvice` + `Result<T>` |
| **字段命名混乱**（前端有的 camelCase 有的 snake_case） | 全链路统一 snake_case（Jackson `SNAKE_CASE`）|

**这句可以背：** "我把原来几个真实的 bug 都定位并修掉了，其中最典型的是越权漏洞——原来任何登录用户都能接受/拒绝任意投标，现在在 Service 层做了资源归属校验。"

## 7. 高频问答速记

**Q：分页怎么实现的？**
A：MyBatis-Plus 的 `PaginationInnerInterceptor`，Mapper 方法第一个参数传 `Page`，自定义 SQL 用 `<script>` 动态拼条件，返回 `IPage`，我封装成 `PageResult{items, total}`。

**Q：MyBatis-Plus 和 MyBatis 什么关系？**
A：MP 是对 MyBatis 的增强，`BaseMapper` 提供通用 CRUD，不用写 XML；复杂联表（比如查投标要带厂家名）我仍然用注解写 SQL，两者混用。

**Q：怎么防止别人改别人的数据？**
A：从 `SecurityContext` 取当前用户（`SecurityUtil.getCurrentUserId()`），在 Service 层比对资源归属，不匹配抛 403。方法级 `@PreAuthorize` 管"角色能不能调这个接口"，Service 里再管"这条数据是不是你的"——**两层都要有**。

**Q：逻辑删除 vs 物理删除怎么选？**
A：业务数据用逻辑删除（可追溯、可恢复），我这个项目四个业务表都用 `deleted` 标记；只有真正要清数据才物理删。

**Q：为什么 DTO / VO / Entity 要分开？**
A：实体对应表，出参要脱敏（比如用户不能带密码）、还要组装（比如投标要带厂家名），入参要做校验。分开后各自职责清晰，也不会把表结构泄漏给前端。
